# run-cli-agent-task

用户要求用 opencode 或 qoder 执行特定任务时，把对应 CLI 当作子智能体：理解用户意图，组织成一份自包含的任务描述，派发给它执行，并等待其返回结果。

## Use When

用户要求用 opencode 或 qoder（QoderCN）去做某个任务，例如「用 opencode 执行 xxx」「让 opencode 跑一下这个任务」「用 qoder 执行 xxx」。仅提到工具名而不要求执行任务时，不要触发。

## 命令对应关系

| 工具 | 命令 |
| --- | --- |
| opencode | `opencode run "<任务描述>"` |
| qoder（正名 QoderCN） | `qoderclicn --print "<任务描述>"` |

两者均为非交互模式：接收任务描述，执行完输出结果并退出。假定对应 CLI 已在 PATH 中，直接调用，不做安装路径探测。

## Steps

1. 理解用户意图，把任务组织成一份自包含的任务描述：子智能体没有当前会话的上下文，任务描述必须自带目标、范围、约束、涉及的文件/目录、验收标准，让它无需追问即可执行。然后在当前智能体的工作目录下派发（CLI 的工作目录必须与当前智能体的工作目录一致）：

   ```bash
   opencode run "<组织好的任务描述>"
   # 或
   qoderclicn --print "<组织好的任务描述>"
   ```

   即调用时的 shell 当前目录就是本会话工作目录，不要 `cd` 到别处。

2. 直接等待命令执行完成，结束后读取输出并核对退出码。任务耗时可能较长，用 `run_in_background` 启动，但启动后不要中途反复轮询输出，等它自然结束再一次性读取。

## Rules

- 派发前先理解用户意图再组织任务描述：不是逐字转发用户原话，而是把 CLI 当子智能体，补齐它缺失的上下文（目标、范围、约束、文件位置、验收标准）。
- 不使用交互模式；`run` / `--print` 均为非交互执行。
- 调用时不得切换工作目录：CLI 必须在当前智能体的工作目录下执行，`cd` 到其他目录会改变任务上下文。
- 假定 CLI 已在 PATH 中，直接调用，不做安装路径探测。
- 命令失败时把退出码和错误输出如实反馈给用户，不自行重试。

## Notes

- 子智能体的任务在其自身工作区/会话中执行，与当前会话相互独立，结果以命令输出为准。
- 长时间无输出属正常现象，继续等待，不要中断。
- 等待期间不要反复尝试读取输出，等执行结束后再一次性读取。
